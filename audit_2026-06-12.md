## 2. Critical gaps (defense-blocking)

1. **The 5–8× simulator quality gap is the most important unresolved scientific fact.** In `quantum_1` (simulator, n=20, seed=0), quantum neighborhoods score 17.7–21.4% RPD vs 2.6–3.8% classical. This is *not* hardware noise — it's formulation or implementation. A QPU run will not beat the simulator (it adds embedding overhead, chain breaks, analog noise). Candidates: penalty-weight mis-scaling, wrong move granularity, or a config bug — the `fibonahi` 18% vs `fibonacci` 3.8% anomaly inside the same batch suggests the latter is plausible. **Diagnose before spending quota.**
2. **`quantum_qubo_enhanced` has zero execution history.** The PAN paper's central novelty (windowed decomposition, K≤180 vars, adj→n=200, fib→n=500, dyn/motz→n=50) rests on code that has never run. No evidence it produces valid permutations.
3. **QAOA deleted but still in the thesis topic.** `src/qaoa/` had 5 modules until ~3 May; only `__pycache__` remains. Either restore from git history and produce a minimal n=20 result, or formally narrow the thesis scope. Pick one explicitly.
4. **Dynasearch n=500 results unusable (bug).** A single neighborhood evaluation takes ~172 s regardless of `tl=100ms` or `10s` — TL enforcement broken; results not comparable. Plus 108/110 result files are missing from aggregated CSVs (summary generated before runs finished). Motzkin n=500 is absent entirely.
5. **Reproducibility:** `dwave-ocean-sdk`/`dimod` not pinned in requirements.txt; `src/experiments/latex_export.py` deleted (pycache only); `fibonahi`/`fibonacci` naming split silently breaks CSV joins.
